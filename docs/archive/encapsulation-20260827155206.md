## Architectural Accomplishments & Encapsulations

1. **Standard Media & Item File Serving (`mods/common/common_response.c` & `mods/common/common.h`)**:
   - `respond_item_file(int fd, const char *item_path, const char *filename, const char *allowed_exts)` encapsulates safe path lookup, safe identifier check, extension allowlisting, mime type resolution, fstat, chunked streaming, and empty file handling.
   - Reduced `poem.c` media asset handling from ~70 lines of custom fopen/fstat/fread/mime mapping to 2 lines (`respond_item_file(fd, ctx->item_path, file, "jpeg,jpg,png")` and `respond_item_file(fd, ctx->item_path, "pt_PT.html", "html")`).

2. **Standard Item Detail Page Responder (`mods/common/common_response.c` & `mods/common/common.h`)**:
   - `site_ui_respond_item_detail(int fd, const item_ctx_t *ctx, const char *module, const char *title, bud_node *body)` encapsulates item path construction, page title formatting, module icon lookup, owner verification, `site_ui_item_menu` creation, `site_ui_layout` wrapping, and response dispatch in 1 call.
   - Refactored `poem.c` and `grp.c` to use this declarative helper, eliminating repetitive layout assembly and boilerplate.

3. **UX Declarative Sub-Item Row & Action Components (`mods/common/ux/site_forms.c` & `mods/grp/ux/detail.c`)**:
   - `site_ui_action_form` and `site_ui_item_row` primitives deployed in `grp/ux/detail.c` to eliminate JSX boilerplate for actionable child items (e.g. set key, remove pinned song).

4. **Zero Compiler Warnings & Strict Types**:
   - Resolved all type forward declarations (`struct item_ctx_s` in `common.h`, header prototypes in `common_internal.h`).
   - Clean compilation across all modules with zero warnings and full boundary checks passing.
