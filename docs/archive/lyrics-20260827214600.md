# Task: lyrics

## Goal
Implement a pure in-memory derived `lyrics` field dynamically computed from `data.txt` (via `libtransp`), eliminating all `lyrics.txt` files on disk, ensuring clean lyric indexing (excluding chord symbols), supporting multi-field FTS composition, and establishing robust local build & dependency pipeline invariants with zero encapsulation breaches.

## Current Status
- **Status**: Completed, Verified & Encapsulation Audited.
- Full test suite passing with 100% success (`make test` passed 99/99 E2E tests, unit tests, pages smoke tests, and matrix tests).
- All architectural boundaries intact:
  - `external/bud`: Pure UI layer, 0 database/storage concepts.
  - `external/hyle`: Canonical schema & data engine, 0 DOM/JSX concepts.
  - `external/hyle/c/libhyle-bud`: Pure UI-bridge rendering.
  - `external/hyle/c/libhyle-source`: Dedicated dataset storage & persistence.
  - `mods/song`: Clean consumer module with in-memory derived lyrics.

## Architectural Invariants & Review
1. **Clean Lyrics Derivation (In-Memory)**:
   - `data.txt` is the sole source of truth on disk.
   - `derive_song_lyrics()` in `mods/song/song.c` extracts lyric lines via `transp_song_parse()` dynamically during indexing into a thread-local buffer.
   - Zero `lyrics.txt` files generated or stored.
2. **Schema & Engine Plumbing**:
   - `DERIVED_FIELD(lyrics, "song.lyrics_from_data")` registered in `mods/song/fields.h`.
   - `hyle_schema_desc_t` and `libhyle-source` pass `derive_key` through to `libhyle` and `stoma`.
   - `source_to_hyle_type()` maps `HYLE_SOURCE_FIELD_DERIVED` $\rightarrow$ `HYLE_FIELD_DERIVED` with `searchable = 1`.
3. **Multi-Field FTS & Omnisearch Composition**:
   - Omnisearch (`row_matches_q`) and multi-field filters (`prefilter_fts`) query derived fields via `hyle_call_derive()`.
   - Single-field search (`?lyrics=amazing`), multi-field filters (`?title=grace&lyrics=sweet`), and omnisearch (`?q=...`) all work consistently without chord symbols polluting results.
4. **Build & Include Pipeline Hardening**:
   - Makefiles across `external/mk/include.mk` now generate `.d` dependency files (`-MM -MT $@ $< > $@.d`), guaranteeing that modifications to `.h` files immediately trigger recompilation of all dependent `.c` files.
   - Local-first include & rpath flags ensure build and tests always run against local submodule binaries.
5. **Encapsulation & Boundary Checks**:
   - `scripts/check-module-boundaries.sh`, `scripts/check-ux-purity.sh`, and `scripts/check-wasm-imports.sh` all PASS with 0 violations.

## Constraints & Rules
- Pure-C only. No JavaScript for search or derivation logic.
- UX purity & WASM safety strictly enforced.
- SSR contract preserved with full No-JS functionality.
- Automated dependency tracking in Makefiles.

## Decisions made
- No `lyrics.txt` files on disk.
- `lyrics` is derived in-memory on demand during indexing via `hyle_register_derive`.
- `data` field is excluded from FTS indexing; `lyrics` is indexed.
- `lyrics` participates in multi-field FTS filtering (composed with `title`, `author`, `type`, etc.) and omnisearch (`q`).
- Added automatic `.d` dependency tracking to `external/mk/include.mk`.
