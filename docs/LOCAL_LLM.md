# Local LLM Inference & Pi Agent Integration (axil-auren)

`axil-auren` (`libauren`) provides ultra-fast in-process LLM inference, OpenAI-compatible streaming chat, and dense vector embeddings powered by `llama.cpp` and Vulkan/CPU, served as a native axil module on port `4242`.

---

## 1. Quickstart: Starting the Server

The turnkey launcher script starts `axil-auren` with automatic library paths and configuration discovery:

```bash
# Launch server on default port 4242:
/home/quirinpa/axil-auren/scripts/auren-server

# Or customize port:
AUREN_PORT=4242 /home/quirinpa/axil-auren/scripts/auren-server
```

Or run directly via `axil`:
```bash
LD_LIBRARY_PATH=/home/quirinpa/axil-auren/lib \
axil -A -d -p 4242 -m /home/quirinpa/axil-auren/lib/libaxil-auren
```

- **Dense Vector Embeddings (Fast & Lightweight)**: `~/.models/bge-small-en-v1.5.gguf` (37 MB, Q8_0, 384-dimensional)

### B. Session Continuity Extension (`~/.pi/agent/extensions/auren-prefix-cache.ts`)
The extension hooks into Pi's provider lifecycle to bind each interaction to the active workspace session ID:

```ts
export default function aurenPrefixCache(pi: any) {
  function getActiveSessionId(ctx: any): string {
    return ctx?.sessionManager?.getSessionId?.() || "default-session";
  }

  pi.on("before_provider_headers", (event: any, ctx: any) => {
    if (ctx?.model?.provider === "auren") {
      event.headers["x-session-id"] = getActiveSessionId(ctx);
    }
  });

  pi.on("before_provider_request", (event: any, ctx: any) => {
    if (ctx?.model?.provider === "auren") {
      if (event?.payload && typeof event.payload === "object") {
        event.payload.session_id = getActiveSessionId(ctx);
      }
    }
  });
}
```

## 4. How Session Continuity & KV Prefix Caching Works

In agent coding workflows, system prompts, tool schemas, and workspace rules typically exceed 10,000–15,000 tokens. Evaluating this from scratch on every turn creates substantial delay on CPU.

`axil-auren` solves this via **Two-Sided KV Prefix Persistence**:
1. When Pi sends a request, the `x-session-id` header (or JSON `session_id`) identifies the session.
2. `axil-auren` allocates or retrieves an LRU session slot in `g_engine.sessions` owning a persistent context.
3. The conversation template is tokenized in full and compared against `cached_tokens`.
4. Downstream divergent cells are evicted via `llama_memory_seq_rm()`, and only the new turn suffix is evaluated starting explicitly at position $K$.
5. **Speedup**: Ingesting a 3,500+ token context drops from **30.5 seconds on Turn 1** to **2.0 seconds on Turn 2** (**15x+ speedup**), decoding only ~17 delta tokens.

## 6. Decision Judging & Status Indicators (`pi-quest` & `pi-mm`)

`axil-auren` serves high-efficiency decision endpoints for autonomous Pi extensions:
- **`POST /api/v1/systemzero/`**: Zero decode passes. Evaluates the prompt forward pass and extracts raw output logits from `llama_get_logits_ith(ctx, -1)`, computing exact sigmoid probabilities ($P = \sigma(L_y - L_n)$).
- **`POST /api/v1/systemone/`**: Full Jev-compatible structured question evaluation over conversational state.

### Client Configuration (`judgeProtocol`)
The defaults work with no settings at all (local server on `:4242`). Override in `.pi/settings.json` only to deviate:
```json
{
  "pi-quest": { "judgeUrl": "http://127.0.0.1:4242", "judgeProtocol": "systemone", "judgeModel": "olmoe" },
  "pi-mm":    { "judgeUrl": "http://127.0.0.1:4242", "judgeProtocol": "systemone", "judgeModel": "olmoe" }
}
```
Protocol options:
- `"systemone"` (default): standard Jev choice question payload (`/api/v1/systemone/`). A single closed choice question is answered from option-letter logits in one forward pass with real softmax probabilities; generation is capped (64 tokens) so one request can never wedge the single engine worker; a reply that is not exactly one declared option is returned as `"choice": null`, which clients treat as "judge unavailable" (there is no silent first-option fallback).
- `"systemzero"`: axil-auren's fast binary endpoint (`/api/v1/systemzero/`). Measured weaker on small models (3/8 with `qwen`, 6/8 with `olmoe` on a quest-vs-chat check), so it is opt-in.
- `"auto"`: attempts System Zero first, falls back to System One.

### Classifying with embeddings, not the judge (where it was measured to win)
Small local judges are biased on closed questions: reordering the options changes the answer, and on `olmoe` three of the questions collapse to one answer (difficulty never says "standard", memory capture always says "remember", plan verification always says "yes") while quest-vs-conversation answers both ways but opens many false quests. So `pi-quest` and `pi-mm` decide the following with `POST /v1/embeddings` (`bge-base`, ~15 ms) and the nearest labelled example sentence, accepting a state-changing verdict only with a similarity floor and a margin over the runner-up. Each move was measured on held-out English/Portuguese corpora and adopted only with zero wrong state-changing verdicts:

| Decision | Decided by | Held-out result (embeddings vs judge) |
| :--- | :--- | :--- |
| Operator steering ("go on", cancel, a constraint) | embeddings | 43/48, 0 false actions (judge: 1 of 7 approvals) |
| Quest or conversation (`pi-quest`) | embeddings, judge as fallback | 0 false quests vs 11 (same 73% accuracy) |
| Difficulty (`pi-quest`) | embeddings, judge as fallback | 0 wrong "trivial" vs 52 over 135 requests |
| Store this turn? (`pi-mm`, `captureMode: "judge"`) | embeddings, judge as fallback | 0 false "remember" vs 20; recall of real memories is low (4/22) |
| Does the plan have a verification step? (`pi-quest`) | **the judge** (embeddings not adopted) | embeddings would wrongly block 8 of 22 good plans; the judge answers "yes" to every plan |

Embeddings are high-precision and low-recall on purpose: a miss costs one `go`, `/quest` or `@remember`, a wrong state change costs more. See `.pi/extensions/pi-quest/docs/OPERATOR_GUIDE.md` (*What Decides What*) and `.pi/extensions/pi-mm/README.md` (*Automatic Capture*) for the settings, the offline fallbacks and the opt-in live evaluations. The `bge-*` models are English-only; add exemplars in your language or use a multilingual embedding model.

### Independent Status Indicators in Pi
Each extension manages its own dedicated footer status slot without collision:
- **`pi-quest`**: Slot `"quest-judge"` (`⚖️q`)
- **`pi-mm`**: Slot `"mm-judge"` (`⚖️m`)

Semantic states:
- 🟢 **Green (`success`)**: Judge online and ready / positive decision with latency.
- 🟡 **Yellow (`warning`)**: Decision currently in-flight.
- ⚪ **Muted**: Conversational pass / skipped / heuristic idle.
- 🔴 **Red (`error`)**: Configured endpoint unreachable (fallen back to heuristic).
