 Architecture & Engineering Specification: NeverDark 2.5D Seven Renderer with 3D Terrain

 ────────────────────────────────────────────────────────────────────────────────

 1. System Philosophy & Strict Separation of Concerns

 ```
                                  ┌────────────────────────────────────────────────┐
                                  │           NeverDark Procedural Engine          │
                                  │  - Field Engine: nd_field_sample()             │
                                  │  - Heightfield:  H(wx, wy)                     │
                                  │  - Water Table:  W(wx, wy)                     │
                                  │  - Spatial Objs: (wx, wy, Z, SpriteID)         │
                                  └───────────────────────┬────────────────────────┘
                                                          │
                              ┌───────────────────────────┴───────────────────────────┐
                              │                                                       │
                [Server Side: Pure Software]                                [Client Side: Hardware WebGL]
                - Target: Native Linux / OpenBSD .so                        - Target: htdocs/nd.wasm in Browser
                - Environment: Headless, No GPU, No GL                      - Environment: Web HAL (lamina-bridge.js)
                - Execution: Pure C CPU blitter                             - Execution: GPU Vertex/Fragment Shaders
                - Memory: Writes flat 2D frame to g_lamina_fb               - Memory: GPU VBOs for 3D Terrain & Quads
                - Job: SSR initial HTML shell & fallback                    - Job: 60 FPS 3D Tilted Perspective
 Diorama
 ```

 ### The Invariant

 1. Server (mods/nd/nd.so): Remains 100% pure software in C. Zero WebGL, zero GPU dependencies, zero display server
    assumptions. It renders the fallback 2D frame into g_lamina_fb using CPU rasterization.
 2. Client (htdocs/nd.wasm + WebGL): Runs in the browser via WASM and takes full advantage of hardware acceleration.
    It evaluates the 3D camera projection, elevates the terrain mesh to Z = H(wx, wy), tests against the hardware
    depth buffer, and blits upright billboard sprites at their true (x, y, z) elevations.

 2. Coordinate Systems & The Subtle-Tilt Camera Geometry

 ### World Space Coordinates

 - X axis: West → East (increases horizontally to the right).
 - Y axis: North → South (increases downwards in room index; in continuous coordinates, 1 room = 160 × 128 units).
 - Z axis: Nadir → Zenith (elevation above sea level; increases upward into the sky).

 ### Orbital Camera Parameters

 The camera centers on the player/lamb target point T = (Tₓ, T_y, T_z) where T_z = H(Tₓ, T_y):
 - Pitch Angle (θ): 55^∘ from horizontal (tilted down towards North).
 - Yaw Angle (ϕ): 0^∘ (aligned facing North, along -Y).
 - Distance (D): 18.0 world units (calibrated so the visible screen width matches the 7×7 NeverDark room window).
 - Vertical Field of View (α): 45^∘ perspective.

 ### Vector Mathematics

 vec(Forward) = ⎛ 0          ⎞ ≈ ⎛ 0       ⎞
                ⎜ -cos(55^∘) ⎟   ⎜ -0.5736 ⎟
                ⎝ -sin(55^∘) ⎠   ⎝ -0.8192 ⎠

 vec(Up) = ⎛ 0          ⎞ ≈ ⎛ 0       ⎞
           ⎜ -sin(55^∘) ⎟   ⎜ -0.8192 ⎟
           ⎝ cos(55^∘)  ⎠   ⎝ +0.5736 ⎠

 vec(Right) = ⎛ 1 ⎞ (East)
              ⎜ 0 ⎟
              ⎝ 0 ⎠

 ### Camera Eye Position in World Space

 E⃗ = ⎛ Tₓ                  ⎞
     ⎜ T_y + D · cos(55^∘) ⎟
     ⎝ T_z + D · sin(55^∘) ⎠

 The camera sits South of the lamb (+Y) and elevated in the sky (+Z), looking down and North towards the lamb.

 ### The Projection Formula

 For any world point P⃗ = (x, y, z) on the terrain:
 - Offset relative to camera eye: Δ⃗ = P⃗ - E⃗.
 - Camera-space coordinates:
   X_cam = Δ⃗ · vec(Right) = x - Eₓ
   Y_cam = Δ⃗ · vec(Up) = Δ · (-sin θ) + Δ · (cos θ)
                          y              z
   Z_cam = -Δ⃗ · vec(Forward) = Δ · (cos θ) + Δ · (sin θ)
                                y             z

 Projected onto normalized device coordinates:

                   X_cam
 x_ndc = ─────────────────────────
         Z_cam · tan(α/2) · aspect

              Y_cam
 y_ndc = ────────────────
         Z_cam · tan(α/2)

 #### Why This Creates True 3D Hills:

 In Y_cam, notice that higher elevation (z > 0) contributes +Δ_z · cos(55^∘) > 0.
 A hill rising in +Z pushes the projected vertex upward on screen, exactly matching the visual reality of looking at
 a hill from a tilted aerial angle!

 3. Continuous 3D Terrain Mesh (Client Hardware Pipeline)

 ### Data Source

 In nd_seven_ground.c, chunk_get_or_create() evaluates continuous planetary elevation and water tables:

 ```c
   nd_field_sample_t fs = nd_field_sample(world, 3, wx, wy);
   chunk->height[idx] = fs.elevation; // int16_t elevation in world units
   chunk->pixels[idx] = pixel_col;    // 32-bit RGBA biome substrate + diffuse sun hillshading
   chunk->depth[idx]  = fs.depth;     // Water depth = W - H
 ```

 ### GPU Mesh Representation

 Instead of uploading a flat 2D rectangle to the canvas, the WebGL pipeline constructs an indexed grid mesh:
 - Grid Resolution: 80 × 64 quads per chunk (or 160 × 128 for 1:1 sub-pixel density).
 - Vertex Layout (32 bytes per vertex):
   ```c
     typedef struct {
         float x, y, z;       // World coordinates (x, y, Z = H(wx, wy))
         float nx, ny, nz;    // Analytical surface normal from dH/dx, dH/dy
         float u, v;          // Texture coordinates into chunk->pixels
     } nd_terrain_vertex_t;
   ```

 ### Analytical Surface Normals (from nd/terrain.h)

 The fine octaves in nd/field.h are mathematically Lipschitz continuous. Surface gradients are computed analytically:

 dh_dx = H(wx + 1, wy) - H(wx - 1, wy)

 dh_dy = H(wx, wy + 1) - H(wx, wy - 1)

 N⃗ = normalize⎛ -dh_dx ⎞
              ⎜ -dh_dy ⎟
              ⎝ 1.0    ⎠

 ### Vertex Shader (VS_TERRAIN_3D)

 ```glsl
   #version 300 es
   layout (location = 0) in vec3 aPos;    // x, y, z = H(x, y)
   layout (location = 1) in vec3 aNormal; // surface normal
   layout (location = 2) in vec2 aUV;     // texture UV

   uniform mat4 uMVP;
   uniform vec3 uSunDir; // Northwest sun: normalize(vec3(-1.0, -1.0, 1.5))

   out vec2 vUV;
   out float vLight;

   void main() {
       vUV = aUV;
       float diff = max(dot(aNormal, uSunDir), 0.25);
       vLight = diff;
       gl_Position = uMVP * vec4(aPos, 1.0);
   }
 ```

 ### Fragment Shader (FS_TERRAIN_3D)

 ```glsl
   #version 300 es
   precision mediump float;
   in vec2 vUV;
   in float vLight;
   uniform sampler2D uSubstrateTex; // chunk->pixels
   out vec4 FragColor;

   void main() {
       vec4 col = texture(uSubstrateTex, vUV);
       FragColor = vec4(col.rgb * vLight, col.a);
   }
 ```

 4. Multi-Elevation Billboard Pipeline (Entities with Z)

 Every dynamic object in NeverDark possesses a 3D coordinate (wx, wy, Z) and an upright billboard geometry:

 ```
             [Top-Left]                  [Top-Right]
              (x - 0.5W, y, Z + H)        (x + 0.5W, y, Z + H)
                        ┌──────────────────┐
                        │                  │
                        │   Sprite Body    │
                        │   (Tree / Mob)   │
                        │                  │
                        └────────┬─────────┘
              (x - 0.5W, y, Z)   │        (x + 0.5W, y, Z)
             [Bot-Left]          ▼        [Bot-Right]
                            [Foot Contact]
                             (wx, wy, Z)
 ```

 ### Billboard Vertex Construction

 Because living entities, trees, and rocks stand vertically along world +Z, their quads are generated on the GPU
 using:

 vec(Right)_cam = (1, 0, 0)

 vec(Up)_world = (0, 0, 1)

 Given world position (x, y, Z), sprite width Wₛ, height Hₛ, and anchor (aₓ, a_y) (default (0.5, 0.0) for feet):
 - Corner 0 (Bottom-Left): ⎛ x - aₓ Wₛ  ⎞
   ⎜ y          ⎟
   ⎝ Z - a_y Hₛ ⎠
 - Corner 1 (Bottom-Right): ⎛ x + (1 - aₓ) Wₛ ⎞
   ⎜ y               ⎟
   ⎝ Z - a_y Hₛ      ⎠
 - Corner 2 (Top-Right): ⎛ x + (1 - aₓ) Wₛ  ⎞
   ⎜ y                ⎟
   ⎝ Z + (1 - a_y) Hₛ ⎠
 - Corner 3 (Top-Left): ⎛ x - aₓ Wₛ        ⎞
   ⎜ y                ⎟
   ⎝ Z + (1 - a_y) Hₛ ⎠

 ### Entity Classification across Z-Levels

 ┌──────────────────┬─────────────────┬─────────────────────────────────────────────────────────────────────────────┐
 │ Entity Category  │ Elevation Model │ Visual Behavior                                                             │
 ├──────────────────┼─────────────────┼─────────────────────────────────────────────────────────────────────────────┤
 │ The Lamb &       │ Z = H(wx, wy)   │ Feet ride the continuous elevation curve. As the lamb walks up a dune or    │
 │ Players          │                 │ hill, its foot position rises along the terrain slope.                      │

 ### Alpha Cutout (Crucial for Z-Buffer Correctness)

 2D sprite textures have transparent borders. In 3D, transparent pixels must never write to the depth buffer, or they
 create invisible occlusion boxes. The fragment shader discards transparent pixels:

 ```glsl
   vec4 col = texture(uSpriteTex, vUV);
   if (col.a < 0.1) discard; // Leaves depth buffer untouched for background terrain
   FragColor = col;
 ```

 5. Translucent 3D Water Plane

 ### Geometry

 The water plane is not a displaced heightfield; it is a horizontal geometric plane situated at the global water
 level:

 Z_water = W(wx, wy)

 ### Bathymetry & Transparency

 From the 55^∘ tilted angle, rays from the camera pass through the water plane at Z = W before striking the seabed at
 Z = H < W:
 - Water Depth: d = W - H.
 - Beer–Lambert Absorption:
   T(d) = e^(-α · d)
     - Shallow shallows (d ≤ 4 units): High transparency (> 80%), allowing the golden sand, submerged pebbles, and
       swimming fish to be seen clearly.
     - Deep ocean (d > 20 units): Dark navy/turquoise opacity, with wave caustics and highlights moving across the
       top surface.

 6. Input & Ray-Plane Intersection (Picking on 3D Terrain)

 When the player clicks on the canvas at screen pixel (sₓ, s_y):
 1. Transform (sₓ, s_y) to Normalized Device Coordinates:
                                            2 s
              2 sₓ                             y
    x_ndc = ──────── - 1.0, y_ndc = 1.0 - ────────
            W_canvas                      H_canvas
 2. Unproject near and far clipping points using (uMVP)⁻¹:
    P⃗ₙₑₐᵣ = (uMVP)⁻¹ ⎛ x_ndc ⎞, P⃗_far = (uMVP)⁻¹ ⎛ x_ndc ⎞
                     ⎜ y_ndc ⎟                   ⎜ y_ndc ⎟
                     ⎜ -1.0  ⎟                   ⎜ 1.0   ⎟
                     ⎝ 1.0   ⎠                   ⎝ 1.0   ⎠
 3. Form the picking ray: R⃗(t) = P⃗₀ + t · D⃗ with D⃗ = normalize(P⃗_far - P⃗ₙₑₐᵣ).
 4. Solve intersection with the local terrain surface Z = H(x, y) using a 4-step secant iteration starting from the
    mean ground plane. This yields the exact world coordinate (wx, wy) under the cursor for tile harvesting, item
    interaction, and pathfinding.

 ### File 2: site/external/liblamina/htdocs/lamina-bridge.js

 Upgrade the browser bridge from a flat 2D screen quad to a hardware WebGL 3D pipeline:

 #### A. Static Terrain Grid Mesh VBO

 Generate a pre-computed grid of 160 × 128 vertices (2 triangles per cell) stored in a static GPU index buffer.

 #### B. 3D Terrain Vertex & Fragment Shaders

 - Vertex Shader: Displaces each grid vertex (x, y) in the vertical axis using the elevation Z = height[y × W + x]
   and transforms by uMVP (tilted 55^∘ camera):
   ```glsl
     attribute vec2 a_pos; // Normalized cell coord (0..1)
     uniform mat4 uMVP;
     uniform sampler2D uHeightTex; // Continuous planetary elevation
     uniform vec2 uChunkWorldOrigin;
     uniform vec2 uChunkWorldSize;

     varying vec2 v_uv;
     varying float v_elev;

     void main() {
         v_uv = a_pos;
         float elev = texture2D(uHeightTex, a_pos).r; // Encoded elevation in world units
         v_elev = elev;
         vec3 worldPos = vec3(
             uChunkWorldOrigin.x + a_pos.x * uChunkWorldSize.x,
             uChunkWorldOrigin.y + a_pos.y * uChunkWorldSize.y,
             elev
         );
         gl_Position = uMVP * vec4(worldPos, 1.0);
     }
   ```
 - Fragment Shader: Samples the pre-computed substrate color texture (chunk->pixels), which already contains blended
   biomes and sun hillshading.

 #### C. Upright Billboard Shader with Alpha Cutout & Z-Testing

 - Evaluates upright vertical quads facing the camera right vector R⃗ = (1, 0, 0) and standing in world +Z = (0, 0,
   1).
 - Enables gl.enable(gl.DEPTH_TEST); gl.depthFunc(gl.LEQUAL);.
 - In the fragment shader:
   ```glsl
     vec4 col = texture2D(uAtlasTex, v_uv);
     if (col.a < 0.1) discard; // Leaves depth buffer untouched for background terrain
     gl_FragColor = col;
   ```

 #### D. Translucent Water Plane

 - Renders a horizontal plane at Z = water_level.
 - Translucent alpha blending allows viewing the submerged bathymetric seabed sloping beneath the waves.

 ### File 3 & 4: mods/nd/ux/nd_seven_ground.h & nd_seven_ground.c

 chunk->height already contains continuous elevation H(wx, wy) calculated for every cell. We expose a direct query
 helper for entity foot positioning and provide the height buffer to the client flush.

 In nd_seven_ground.h:

 ```c
   /* Single authoritative elevation query for any world coordinate (wx, wy) */
   int16_t nd_seven_ground_elevation(int32_t wx, int32_t wy);

   /* Direct access to current chunk's continuous height buffer */
   const int16_t *nd_seven_chunk_height(const nd_room_chunk_t *chunk);
 ```

 In nd_seven_ground.c:

 ```c
   int16_t nd_seven_ground_elevation(int32_t wx, int32_t wy)
   {
       /* Convert continuous world coordinate to room pos */
       int ti = ndw_fdiv(wx, NDW_TILE_W);
       int tj = ndw_fdiv(-wy, NDW_TILE_H);
       int16_t pos[4] = { (int16_t)ti, (int16_t)tj, 0, 1 };

       const nd_room_chunk_t *c = chunk_find(pos, NULL);
       if (c && c->height) {
           int lx = (wx - ti * NDW_TILE_W) * SCALE;
           int ly = (-wy - tj * NDW_TILE_H) * SCALE;
           if (lx >= 0 && lx < TILE_PX_W && ly >= 0 && ly < TILE_PX_H)
               return c->height[ly * TILE_PX_W + lx];
       }

       /* Fallback to mathematical continuous field evaluator */
       return nd_field_sample(1, 3, wx, wy).elevation;
   }

   const int16_t *nd_seven_chunk_height(const nd_room_chunk_t *chunk)
   {
       return chunk ? chunk->height : NULL;
   }
 ```

 ### File 7: mods/nd/ux/nd_ui.c

 In seven_stage_redraw():
 1. Target the camera on the lamb with pitch θ = 55^∘.
 2. On client WASM: Call lam_terrain_mesh_flush() with both chunk->pixels (color) and chunk->height (elevation).
 3. On server SSR: Execute the pure C software blitter.

 ```c
   static void seven_stage_redraw(void)
   {
       if (!seven_stage_fit(g_stage_w, g_stage_h))
           return;

       int64_t wx = 0, wy = 0;
       nd_seven_world_pos(&client_state, &wx, &wy);
 ```

 ### Summary of What This Delivers

 1. Zero Server Regressions: The server .so builds without GPU/GL symbols, running pure CPU blitting for headless
    SSR.
 2. True 3D Terrain in Browser: The client creates a physical 3D surface mesh with hills rising in +Z and valleys
    sinking in -Z from chunk->height.
 3. Subtle 55^∘ Tilt: Looking North with natural perspective foreshortening.
 4. Upright Billboards with Depth: The lamb, trees, and boulders stand vertically on the slopes at Z = H(wx, wy),
    occluding and being occluded by hills via the hardware Z-buffer.
 5. Translucent Water: Water sits flat at Z = sea_level, allowing players to view the submerged bathymetry.
